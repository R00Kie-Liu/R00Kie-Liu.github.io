# 推导型中文科学博客参照

本参照提炼自科学空间公开文章的高层写作特征，用来写清技术问题，不用于复制苏剑林本人的独特文风。不要照抄原句、惯用语、标题或个人经历，也不要把成稿宣称为某位作者所写。

## 核心气质

把读者当作一起推理的同行。文章可以亲切，但技术判断要靠定义、推导、实验或反例站住，而不是靠口号和情绪。

## 常见起点

优先从以下入口选一个：

1. 一个看似理所当然、其实值得追问的标准做法；
2. 最近读到的论文、实现或实验结果带来的具体疑问；
3. 两种常见方案之间尚未说清的差异；
4. 旧文章或系列问题中还没解决的一环；
5. 一个能把抽象定义说清楚的短例子。

开头可以连续设问，但问题必须决定后续章节，并在正文中得到回答。不要用行业浪潮代替问题。

## 论证推进

一个可裁剪的推理顺序：

1. 说明通常做法及其直觉；
2. 指出直觉在哪个条件下不够；
3. 明确定义、符号和目标；
4. 从简单情形推到一般形式；
5. 用梯度、复杂度、实验或反例比较候选；
6. 解释结果与已有方法的联系；
7. 写出限制、欠严谨处和仍未验证的猜想；
8. 回答开头的问题。

章节标题用短名词或动作标记推理台阶，例如“分析”“推导”“梯度”“实验”“联系”“小结”。不要为了像参照站点而机械复用这些词，标题必须与正文实际功能一致。

## 语言习惯

- 使用“我们”可以营造共同推理感，但不必句句出现；“笔者”只在表达个人判断或工作来源时使用。
- 允许“很遗憾，并不对”“更准确地说”“反过来”等自然转折，只在逻辑确实转向时使用。
- 抽象概念后接一个准确、略带生活感的例子，再回到数学或工程定义。
- 技术术语保留通行英文，不为纯中文而硬译；首次出现时按读者需要给中文解释。
- 可以有长句和长段落，尤其是连续推导；在结论、否定或换挡处用短句。
- 破折号、引号、括号和分号按语义使用，不设机械配额。密集出现时检查是否承担了过多旁支。

## 可信度细节

- 主动区分“可以证明”“直觉上”“经验上”“我们猜测”“尚未验证”。
- 对不严谨处加注说明具体缺口，不用笼统免责声明。
- 引用论文、旧文和实现时给链接或可核查名称。
- 不把实验观察写成普遍定律，也不把理论可能性写成工程收益。
- 结论若依赖激活函数、分布假设、数据规模或实现细节，明确写出条件。

## 结尾

技术小结不是 AI 痕迹。只要它确实压缩了本文的推理链，就可以保留。好的小结回答：

- 从什么问题出发；
- 得到了什么结果；
- 为什么比原直觉更准确；
- 哪些部分还不能下结论。

避免额外添加“意义重大”“未来广阔”或泛泛祝语。

## 与通用 humanizer 规则冲突时

以真实样文和技术表达为准：

- 不执行“破折号一律为零”；
- 不要求每 150 字插入碎句；
- 不把所有总结段视为模板；
- 不为提高所谓 perplexity 选择生僻近义词；
- 不人为加入跑题、情绪或不完美。

这些硬规则可能让英文营销文案显得不那么模板化，却会破坏中文推导文章的严谨性。
